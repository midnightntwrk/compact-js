## High-level summary

compact-js 3.0.0 moves the ledger 9 era onto compact runtime 0.21 and compactc 0.36, and builds
ledger 9 against `@midnightntwrk/ledger-v9` 1.0.0. The three packages now publish as ESM only.
Contracts compiled with compactc 0.35 or earlier have to be recompiled to run on the ledger 9
era, and that has consequences for contracts already deployed — the Breaking changes section
below carries the detail. The ledger 8 era is untouched.

## Audience

These notes are written for:

- Developers building DApps on the `@midnight-ntwrk/compact-js` packages.
- Developers who compile Compact contracts with compactc and execute them from TypeScript.
- Shielded Technologies engineering teams maintaining consuming SDKs.

## Dependencies

- Requires compactc 0.36 for contracts executed on the ledger 9 era: artefacts from compactc 0.35
  or earlier declare compact runtime 0.20 and fail the runtime version check on import
  (commit bfa165f).
- Requires an ESM-capable consumer: a CommonJS `require` of these packages resolves only through
  Node's `require(esm)` support (commit 2a0fa26).
- The ledger 8 era (`/v8`, `/v8/effect`) stays on compact runtime 0.16 and takes no recompilation
  (commit bfa165f).

**Downstream impact (cascading effects).** A consuming SDK or DApp that takes compact-js 3.0.0 for
its ledger 9 path inherits the compactc 0.36 requirement for every contract it executes on that
era, and has to ship ESM. Consumers holding both eras in one process keep their ledger 8 artefacts
as they are.

## What changed

- Moved the ledger 9 era to compact runtime 0.21 and compactc 0.36 (PR #40).
- Built ledger 9 against `@midnightntwrk/ledger-v9` 1.0.0 and pinned the on-chain runtime to 4.0.0 (PR #41).
- Fixed the gas-budget rejection of calls that overwrite existing ledger state (PR #38).
- Moved the ledger 8 era to the final `@midnightntwrk/ledger-v8` 8.1.3 (commit 11d098a).
- Removed the CommonJS build; the packages publish as ESM only (commit 2a0fa26).
- Release plumbing and version bumps across the release-candidate line are not listed individually (PR #39).

## New features

### Era-selectable entry points

**Description**: the packages expose `/v8`, `/v8/effect`, `/v9` and `/v9/effect` beside the unsuffixed entry, so a consumer picks the ledger era at import rather than taking whichever era the package binds; both eras can be live in one process, and the unsuffixed entry remains the default for a configuration that names no era (`package.json`).

## New features requiring configuration updates

### Contract artefacts compiled with compactc 0.36

**Required updates**: before the first run on this release.

- Recompile ledger 9 contract sources with compactc 0.36 and repoint the ZK asset paths at the new output (commit bfa165f).
- Leave ledger 8 artefacts on the toolchain that produced them; the `/v8` entry is unchanged (commit bfa165f).

**Impact**: artefacts built by compactc 0.35 or earlier declare compact runtime 0.20 and are
rejected by the runtime version check on import, so a ledger 9 configuration cannot load them.
Read the Breaking changes section before recompiling a contract that is already deployed.

## Improvements

### Gas-budget accounting for state-overwriting calls

**Description**: with `@midnightntwrk/ledger-v9` 1.0.0 the transcripts are partitioned with the cost model of midnight-node 2.1.100-rc.4, and calls that overwrite existing ledger state no longer fail the gas-budget check (commit a75c0f3, owner-confirmed 2026-11-05).

## Breaking changes

### Contracts for the ledger 9 era have to be recompiled with compactc 0.36

**What changed**: the ledger 9 era pairs with compact runtime line 0.21 over on-chain runtime v4, so `Ledger.era.runtime` and `CompactRuntime.line` read `0.21` on the unsuffixed and `/v9` entries (commit bfa165f).

**What breaks**: artefacts produced by compactc 0.35 or earlier declare runtime 0.20 and fail the runtime version check on import; and because recompiling changes a contract's verifier keys, a contract that is already deployed cannot simply be re-attached with freshly compiled artefacts — the new keys do not match the keys in the deployed contract's state, and the attach is rejected (commit bfa165f).

**Required actions**: for every affected consumer.

- Recompile ledger 9 contract sources with compactc 0.36 before running them on this release (commit bfa165f).
- For a contract already deployed, pick one of three routes instead of re-attaching: keep the deployed artefacts and the toolchain that built them; replace the deployed verifier keys through the contract's maintenance authority; or redeploy the contract at a new address (TODO: confirm this wording against the compactc 0.36.0 release note once its verifier-key guidance is published, and link it here — owner).
- Pin the toolchain version in CI so a routine rebuild cannot change the keys of a deployed contract (commit bfa165f).

**Code example**: recompiling a contract for the ledger 9 era.

```sh
compact compile --version 0.36 src/counter.compact build/counter
```

### Circuits declared in a contract type can no longer be `pure`

**What changed**: every circuit declared in a contract type has to carry a proof, because the ledger matches a cross-contract call against the called circuit's proof; declaring such a circuit `pure` is a compile-time error, and purity is gone from the runtime's cross-contract API (commit bfa165f).

**What breaks**: a contract type carrying a `pure` circuit declaration stops compiling, and code reading the removed purity fields stops type-checking (commit bfa165f).

**Required actions**: for every affected consumer.

- Remove `pure` from circuit declarations in contract types, and from `contract implements` declarations whose implementing circuit is `pure` (commit bfa165f).
- Disclose the arguments of every cross-contract call; the exemption that applied to `pure` circuits is gone with those declarations (commit bfa165f).

**Code example**: a contract-type circuit declaration.

```
// was: pure circuit foo(x: Field): Field;
circuit foo(x: Field): Field;
```

### Cross-contract calls have to be recompiled

**What changed**: a cross-contract call's proof now binds the callee circuit named at the call site, which the compiler emits as a constant of the call site (commit 444ac16).

**What breaks**: a contract making cross-contract calls that is not recompiled produces calls whose proofs do not bind the callee (commit 444ac16).

**Required actions**: for every affected consumer.

- Recompile every contract that makes a cross-contract call, callee side included (commit 444ac16).
- Apply the deployed-contract routes from the first item above before recompiling anything already on chain (commit bfa165f).

**Code example**: no source change is needed — the behaviour comes from recompiling.

```sh
compact compile --version 0.36 src/caller.compact build/caller
```

### Ledger 9 contract operation version moves from `v3` to `v4`

**What changed**: compactc 0.36 emits only ZKIR v3 verifier keys, so the ledger 9 contract operation version moves from `v3` to `v4`, and maintenance updates built by `ContractExecutable` insert and remove keys at `v4` (commit bfa165f).

**What breaks**: tooling that assumes `v3` operations for a ledger 9 contract, and serialised maintenance updates built against the older operation version (commit bfa165f).

**Required actions**: for every affected consumer.

- Rebuild maintenance updates with compact-js 3.0.0 rather than resubmitting serialised `v3` updates (commit bfa165f).
- Read the Known issues section before submitting a verifier-key removal (https://github.com/midnightntwrk/midnight-node/issues/2375).

**Code example**: the operation version follows the era binding, so no call site changes.

```ts
import { ContractExecutable } from '@midnight-ntwrk/compact-js/v9/effect'
```

### The CommonJS build is removed

**What changed**: the `build-cjs` step and its `tsconfig.cjs.json` are gone, no `dist/cjs` output is produced, and the published manifests reference `./dist/cjs/*.js` neither as `main` nor in their `exports` conditions, so every export resolves to its ESM file (commit 2a0fa26).

**What breaks**: `require('@midnight-ntwrk/compact-js')` fails with `ERR_REQUIRE_ESM` on a Node version or bundler configuration without `require(esm)` support (commit 2a0fa26).

**Required actions**: for every affected consumer.

- Replace `require` call sites with an ESM `import` (commit 2a0fa26).
- Set `"type": "module"` in the consuming package, or use the `.mjs` extension (commit 2a0fa26).

**Code example**: moving a call site to ESM.

```js
// was: const { ContractExecutable } = require('@midnight-ntwrk/compact-js')
import { ContractExecutable } from '@midnight-ntwrk/compact-js'
```

## Known issues

### Verifier-key removal transactions are rejected with `BalanceCheckOverspend`

**Description**: a maintenance transaction that removes a verifier key fails the balance check although the ledger bindings report it as paid, which affects the `v4` maintenance updates built by `ContractExecutable` in this release ([midnight-node issue #2375](https://github.com/midnightntwrk/midnight-node/issues/2375)).

**Workaround (if any)**: none in compact-js — the fix is in the ledger's fee calculation and
reaches consumers when they pick up the ledger release that carries it.

TODO: name the ledger version carrying the fix once it is public (owner)

### `CompiledContract` context fails across identical package copies

**Description**: when two identical copies of a compiled contract package are resolved in one process, building a contract context fails with a raw constructor `TypeError` ([compact-js issue #28](https://github.com/midnightntwrk/compact-js/issues/28)).

**Workaround (if any)**: deduplicate the contract package so a single copy is resolved.

### A valid null `--input-ps` is rejected

**Description**: the CLI's `circuit` command rejects a valid null `--input-ps`, so a contract whose initial private state is `null` cannot be run from the CLI ([compact-js issue #30](https://github.com/midnightntwrk/compact-js/issues/30)).

**Workaround (if any)**: give the contract a non-null initial private state.
