# Release notes

One file per release, named for its version — `3.0.0.md` is the note for compact-js 3.0.0.

```
docs/release-notes/
├── README.md          this file
├── 3.0.0.md           generated notes, one per release
└── overlays/
    ├── TEMPLATE.md    copy this to start an overlay
    └── <version>.md   the human-written half of a release's note
```

The **canonical, public** release note is the **GitHub Release** — these files are the
reviewable copy that lives with the code. The note is generated by `yarn release:prepare`
and merged through the release PR; **CD** then reads it and puts it in two places:

- the **GitHub Release** body,
- a **run artifact**, so it is reviewable from the run page even if a later step fails.

CD never generates or overwrites a note. A missing `docs/release-notes/<version>.md` fails
the release job rather than being filled in automatically.

The generated note follows the v9 component release-note template — the structure
[`3.0.0.md`](3.0.0.md) follows.

## Where the content comes from

| Layer | Source | Carries |
| --- | --- | --- |
| derived | package `CHANGELOG.md`, workspace manifests, `.github/env/global.env` | release type, what changed, breaking changes, features, improvements, tested-with pins, artifacts, fixed defects |
| base | `overlays/_base.md` (optional) | anything stable across releases |
| per-release | `overlays/<version>.md` (optional) | this release's human-only fields |

Each layer overrides the one above it. A field no layer supplies is emitted as a
`TODO (owner):` marker, never dropped — the note is always structurally complete, and the
count of remaining TODOs is printed in the CD job summary.

## The CHANGELOGs are the content source

`changeset version` runs first and writes each package's `CHANGELOG.md`; the generator reads
the section it just added for the version in `compact-js/package.json`. Nothing is derived
from tags or commit history, so a stable release that follows a run of release candidates
reads exactly like one that does not.

| Changeset bump | Section |
| --- | --- |
| `major` | Breaking changes |
| `minor` | New features |
| `patch` | Improvements, and the Fixed defect list |

The highest bump across the release becomes the **Release type**. Every entry also contributes
a **What changed** bullet, cited to the PR that merged it — `@changesets/changelog-github`
records that PR number, so the citation needs no commit archaeology.

One changeset bumps several packages, so its summary appears in several CHANGELOGs; entries are
de-duplicated by summary and keep the **highest** level any package gave them. `Updated
dependencies` roll-ups are ignored. One changeset becomes one item — a changeset describing
several distinct breaking changes produces one item covering all of them, and the overlay is
where it gets split.

Write the changeset so its **first sentence names the change**: that sentence becomes the item's
heading. Sentences over 80 characters are clipped at a clause boundary, with a warning.

## Writing an overlay

Copy [`overlays/TEMPLATE.md`](overlays/TEMPLATE.md) to `overlays/<version>.md` and fill in what
applies. Commit it in the release PR, so the human-written half of the note is reviewed like
any other change. Sections you omit keep their generated content.

The template's guidance lives in HTML comments, which the generator strips — a section you copy
over but never fill in contributes nothing rather than publishing its own instructions.

Three sections merge rather than replace, so an overlay cannot silently freeze a derived value:
**Metadata**, **Deployment information** and **Links and references** merge by `- **Label**:`,
and **Tested-with versions** merges by the table's first column, keeping the generated caveat
about where those versions came from.

## Running it locally

```sh
node scripts/generate-release-notes.mjs --out /tmp/note.md
```

It reads the version from `compact-js/package.json` and needs no install — only `node:*`
built-ins. Add `--version X.Y.Z` to target a different release and `--report <path>` for the
warnings as JSON. `--shasums` reads each tarball's `dist.shasum` from the registry, so it only
works once the packages are published.

Without `--out` it writes `docs/release-notes/<version>.md`, and it refuses to replace a note
that already exists — one may have been hand-edited since. Pass `--force` to replace it.
